# Forgather 1.2.0 release notes

*Released: May 2026*

This is the first formal Forgather release with notes. The headline of 1.2.0
is **multi-node**: the server, the dataset layer, and the web UI now treat a
LAN-attached set of machines as a single Forgather. A 1.1.0 user mostly
trained one machine at a time and either copied a dataset to every node by
hand or paid the indexing cost on every machine; a 1.2.0 user can launch a
multi-node bundle from the web UI, point every rank at one dataset server,
and resume from a checkpoint in O(1) instead of streaming back to the saved
position.

The release also folds in: native HTTPS / mTLS across all three servers,
torchao QAT + PTQ as a unified `--quantize` flow, an `os.execv` in-place
server restart, auto-start services from `server_config.yaml`, a runtime
Docker image suitable for distribution, DGX Spark (GB10, aarch64) bring-up,
plus the long tail of fixes and webui polish that the items below list out.

---

## Headline features

### Multi-node forgather server

`forgather server --cluster <name>` puts a node into cluster mode. Peers
discover each other over mDNS (cluster-name-scoped — separate clusters on
the same LAN never auto-merge), maintain a 5s peer-pull liveness loop, and
elect the lowest-UUID-among-reachable peer as the master.

- **`forgather cluster` CLI** — `nodes`, `jobs`, `submit`, `cancel`. The
  `submit` form mirrors the local `train` shape (`-p` / `-t`), takes
  repeatable `--member host:gpus[:iface]` selectors (hostnames resolve to
  UUIDs via the membership table — no UUIDs in the CLI), and rolls every
  participant's status up into one bundle.
- **Cluster panel in the web UI** — separate Nodes view (cluster-only,
  pinned to the top of Views when active) with per-node row showing
  role / reachability / version / GPU summary; peer GPUs flagged BUSY
  when a peer has the card reserved.
- **Cluster network probe** — `/api/cluster/latency*` (30-sample
  warmup-trimmed RTT) plus an adaptive parallel-stream raw-TCP bandwidth
  probe via `/api/cluster/bandwidth_prep` (HTTPS control plane, plain-TCP
  data plane with a handshake token). Hits wire-speed on 10 Gbps; the old
  single-stream HTTPS probe topped out near 2 Gbps.
- **One-click peer SSO** — clicking a peer hostname in the Cluster sidebar
  group opens its web UI via a fresh `?token=…` URL minted by the local
  node over mTLS. No second token prompt.
- **Per-node restart / shutdown buttons** in the Nodes panel.
- **`forgather server --local-addr`** is now passed through to torchrun so
  `MASTER_ADDR` ends up as an IP, not a hostname that may not resolve on
  every peer.

Docs: [`docs/guides/multi-node-training.md`](../guides/multi-node-training.md).

### Dataset server

A new long-running service that turns datasets into a cluster-shared
resource. The trainer-side dataset loader speaks to it transparently:
existing configs pointing at local Arrow datasets do not need to change.

- **Unified view across nodes** — a dataset registered on any peer is
  reachable from every peer. The dataset client transparently routes
  through the cluster index.
- **Load balancing** — the registry deduplicates by `(type, normalized
  args)` so multiple peers serving the same dataset are pooled as one
  routable endpoint.
- **Streams datasets from remote hosts** — pull rows over the network when
  the corpus does not live on the local node. The NDJSON `/iter` endpoint
  is stateless w.r.t. clients (every call carries seed + position), so
  multiple ranks can share one handle.
- **Stateful dataset protocol** — `state_dict()` / `load_state_dict()` on
  the wire. Resume from a checkpoint seeks directly to the saved position
  (O(1)); previous releases had to stream-and-discard from the start of
  the epoch to catch up.
- **Resilient client** — `ResilientRemoteBackend` catches transient
  errors, 5xx, and 404-on-evicted-handle; retries with exponential backoff
  up to 30 s per attempt and re-issues `POST /v1/load` (idempotent —
  `canonical(load_args) → handle`). A server restart mid-run no longer
  aborts a multi-day training job.
- **Backend abstraction** — `IterableDatasetBackend` ABC + a composing
  wrapper (`map` / `filter` / `select` / `slice` / `shard` / `shuffle` /
  `set_epoch` / `state_dict` / `load_state_dict`). Local Arrow today, the
  remote proxy tomorrow, no rewrite of higher-level operators.
- **Web UI integration** — Tools → Start Dataset Server, dedicated
  Datasets view, submit-modal source selector. Tokens persist across
  webui-launched restarts (mirroring inference-server token persistence).

CLI: `forgather dataset-server start | status | list | cache | local`
(all accept `--server URL`, `--token TOKEN`, `--json`).

## TLS / mTLS

Native HTTPS across `forgather server`, `dataset-server`, and
`inference-server`, off a single per-host config under
`~/.config/forgather/tls/`. One `forgather tls init` enables TLS on a
host; `forgather tls deploy` automates per-peer bring-up for clusters
(mint + scp + remote-install over ssh, `--container NAME` wraps remote
commands in `docker exec`).

- **Shared TLS module** (`src/forgather/tls/`): config loader, CA + leaf
  cert minting, trust-bundle rebuild, non-loopback policy, uvicorn ssl
  kwargs, httpx verify helper. Atomic 0600 key creation, 160-bit random
  serials, SAN size caps, fail-closed when no bundle.
- **`forgather tls` CLI** — twelve subcommands: `init` / `status` /
  `renew` / `mint` / `install` / `deploy` / `enable` / `disable` /
  `export-ca` / `import-ca` / `trust-system` / `clean`.
- **Cluster mTLS** — inter-node `/api/cluster/*_local` calls now
  authenticate by *mutual TLS*. The 1.1.0 source-IP carve-out for peer
  calls is gone; every peer presents its CA-signed `server.crt` as a
  client cert and the receiving auth middleware treats cert presence as
  proof of cluster membership. **Operator action on upgrade**: re-issue
  existing certs to pick up the `CLIENT_AUTH` EKU
  (`forgather tls renew` on the CA holder, `forgather tls mint` +
  `install` for every other peer), then restart every server.
- **Docker runtime image** — `TLS_INIT=1` runs `forgather tls init` on
  first start; `TLS_BAKE_FROM_HOST=1` / `TLS_BAKE_FROM_DIR=PATH` bakes a
  CA + cert into the image for build-once-distribute-N clusters.

Docs: [`docs/operations/tls.md`](../operations/tls.md).

## Server config + auto-start services

A real `server_config.yaml` with two top-level sections:

- **`args:`** — CLI defaults (host, port, cluster name, persist-sessions,
  …). New `--config PATH` arg; default at
  `<forgather_config_dir>/server/server_config.yaml`.
- **`services:`** — auto-start entries for dataset-server, inference,
  TensorBoard, MkDocs. Signature-based dedupe over `(type, normalized
  args)` so restart never double-spawns and manually-launched matching
  jobs count as the running instance.

Sidebar overhaul to expose this:

- **Tools / Services split** — Tools is one-shot (Evaluate / Convert /
  Finalize / Update); Services is long-running (Inference / Dataset /
  TensorBoard / MkDocs) with a running-count pill, per-type expand
  chevron, and a per-instance list with red/green dot, ▶/⏹ toggle, and
  × delete.
- **Sticky sidebar footer** with ⟳ Refresh, ▶/⏸ Scheduler, ↺ Restart,
  ⚙ Open config.
- **In-place `os.execv` restart** via `POST /api/server/restart`. PID
  and TTY preserved; spawned subprocesses (training, inference,
  dataset_server, mkdocs, tensorboard) reattach via the existing
  PID-reattach path. Optional **`--persist-sessions`** stores browser
  sessions in `<config>/server/sessions.json` (0600) so a restart does
  not log every operator out.

Reference: [`tools/forgather_server/README.md`](../../tools/forgather_server/README.md)
(also accessible as [`docs/forgather-server.md`](../forgather-server.md)).

## Quantization: torchao QAT + PTQ unified

A single `--quantize <recipe>` flag on `forgather finalize` covers both
post-training quantization (apply to any bf16 model) and the QAT
round-trip (apply to a model trained with `--qat-recipe`). The 1.1.0
`--qat-convert` name is gone with no compatibility shim.

- **Train-time** — `--qat-recipe` inserts `FakeQuantizedLinear` via
  `torchao.quantize_(model, QATConfig(base, step="prepare"))`. Forward
  simulates the target low-bit precision; backward stays in full
  precision. Mutually exclusive with `--fp8-recipe`.
- **Deploy-time** — `forgather finalize --quantize <recipe>` swaps every
  `FakeQuantizedLinear` for the real low-bit op. Recipes:
  `int8-dynamic-act-int4-weight`, `int4-weight-only`,
  `float8-dynamic-act-float8-weight`, `float8-dynamic-act-int4-weight`.
- **Native loader integration** — `forgather.ml.sharded_checkpoint.load_checkpoint()`
  detects torchao quantization (via `config.json`'s
  `quantization_config`, falling back to a state-dict scan) and installs
  the matching quantized linear modules on the constructed model *before*
  `load_state_dict` runs. No CLI flag, no marker file. Every tool that
  goes through the native checkpoint loader inherits the support:
  `forgather eval test … -M <quantized_dir>`,
  `forgather inf server -m <quantized_dir> --from-checkpoint`,
  trainer `resume_from_checkpoint`. Closes #41 / #42.
- **Webui** — FinalizeModal grows a Quantize dropdown wired into
  `job_params`.

Three-way comparison on 4.43M Tiny Llama (RTX 3090, full Tiny Stories
eval, `int8-dynamic-act-int4-weight`):

| Run            | Eval loss |
| -------------- | --------- |
| bf16 baseline  | 1.366     |
| PTQ on bf16    | 1.392 (+0.026) |
| QAT converted  | 1.391 (+0.025; −0.001 vs PTQ) |

Docs: [`docs/trainers/qat-training.md`](../trainers/qat-training.md).

## Hardware bring-up

- **DGX Spark (NVIDIA GB10, aarch64)** as a first-class cluster member.
  CUDA-enabled aarch64 torch installed from
  `download.pytorch.org/whl/cu128` in both the dev and runtime Docker
  images (PyPI's aarch64 wheel is CPU-only). `docker/build --cpu` flag
  for CPU-only builds.
- **Unified-memory GPUs** (GB10, Jetson) — NVML's "Not Supported" on
  these devices no longer drops the GPU from the panel; host RAM is
  surfaced as the device pool with a `unified_memory` flag. `gpu_flops`
  table adds GB10 at 62 TFLOPS BF16 dense.
- **MFU sanity** — `preprocess.get_peak_hardware_flops` returns a
  pessimistic 30 TFLOPS placeholder when no GPU is recognised, so silent
  fallbacks show up as MFU > 100 % in dashboards instead of a believable
  number.
- **FP8 on Blackwell SM 12.1** — documented NVRTC failure with
  `rowwise` on GB10 (torch 2.10/cu128 bundled NVRTC rejects
  `--gpu-architecture` for SM > 12.0; the recipe's dynamic-scale rounding
  gets JIT-compiled and trips it). Workaround documented; `tensorwise`'s
  cuBLAS path (`torch._scaled_mm`) is unaffected.
- **FP8 warning** — torchao 0.16.0's `rowwise_with_gw_hp` recipe is
  broken for ND inputs; the trainer warns at init so users see it before
  the crash.

## Docker

- **Runtime image** — `Dockerfile.runtime` plus
  `docker/runtime/{build,run,entrypoint}.sh`. Distributable counterpart
  to the dev image; default command is `forgather server`. UID-1000
  in-container user remapped to PUID/PGID via gosu so a single prebuilt
  image works for any host user, and `~/.cache/huggingface` can be
  bind-mounted without ownership drift.
- **NETWORK=host** opt-in (required for the cluster's mDNS discovery,
  which uses multicast and does not traverse the docker bridge).
- **`docker/build.sh → docker/build`, `docker/run.sh → docker/run`** —
  tab-completion ergonomics; old names left in place for one release.
- **TensorBoard patch is now version-gated** — the next image rebuild
  after upstream ships a fix will fail loudly so the patch can be
  retired, instead of silently no-op'ing.
- **Multi-node smoke test** — `scripts/smoke_runtime_multinode.sh` builds
  the runtime image, deploys to a remote host via NFS-shared
  `docker save`/`load`, starts a cluster on both, runs Tiny Llama v2
  across all GPUs, verifies the checkpoint, cleans up. On failure, dumps
  container logs + cluster JSON state + TTY logs + `nvidia-smi` to one
  triage file.

Docs: [`docs/getting-started/docker.md`](../getting-started/docker.md).

## Construct job + tokenizer projects

- **Construct job type** — `forgather construct --enqueue` surfaces the
  diagnostic side of `forgather construct` through the queue/scheduler.
  Targets can be materialised (and side-effecting targets like a
  tokenizer trainer can be invoked) without running inline in the server
  process. A 🔨 Construct… entry appears on every config's context
  menu in the web UI.
- **Tokenizer projects modernized** (`examples/tokenizers/`) — dynamic
  args (`--output-dir`, `--tokenizer-name`, `--model-max-length`,
  `--vocab-size`) on `templatelib/base/tokenizers/tokenizer_type.yaml`,
  so a custom tokenizer can be built entirely from the CLI via
  `forgather construct`.

## Configuration directory

`~/.forgather/` is gone. Per-user state now lives at
`~/.config/forgather/` via `platformdirs` (the older
`forgather_config_dir()` API absorbed the briefly-introduced
`forgather_home_dir()` + `FORGATHER_HOME`). Hard switch with no data
migration: auth tokens regenerate on first use; users with customised
`config.yaml`, `generation_config/*`, or `hardware.yaml` need to move
those by hand. Run `rm -rf ~/.forgather` after upgrading to reclaim the
orphaned dir.

## Bug fixes worth calling out

- **Atomic write mode** — `_atomic.atomic_write_text(path, content)` used
  to call `os.open(tmp, flags)` with no mode, defaulting to 0o777; with a
  typical 0o022 umask, every template-editor save silently chmod'd the
  target from 0o644 to 0o755. Pass 0o666 explicitly so umask trims it to
  0o644. Includes regression tests with a pinned umask.
- **`_atomic.py`** upgraded to `fsync → rename → directory fsync` (full
  POSIX safe-replace).
- **Workspace Edit README.md** repointed at
  `forgather_workspace/README.md` (was pointing at the workspace-root
  sibling, which is not where `forgather ws create` writes the file).
- **`fs.delete_dir`** does `os.sync()` + parent-dir mtime bump after
  `rmtree` to nudge NFS clients toward fresher views.
- **`build_sync`** flushes `os.sync()` + `fsync(dirfd)` on the builder
  before releasing peers and calls `importlib.invalidate_caches()` on
  waiters after the barrier — defeats the most common
  "Unrecognized model — should have a model_type key" race on NFS.

## Breaking changes (read these before upgrading)

1. **Per-user state moved** — `~/.forgather/` → `~/.config/forgather/`.
   No automatic migration. Auth tokens regenerate on first use; copy
   `config.yaml`, `generation_config/`, `hardware.yaml` by hand if
   you customised them. `rm -rf ~/.forgather` once you're done.
2. **`forgather finalize --qat-convert` is now `--quantize`** —
   no compatibility shim. Scripts and webui-saved presets need updating.
3. **Cluster mTLS requires `CLIENT_AUTH` EKU on every peer cert** —
   `forgather tls renew` on the CA holder, then
   `forgather tls mint` + `install` on every other peer, then restart
   every server. Mixed-version clusters where some peers haven't been
   reissued will see silent peer-pull failures.
4. **Docker `build.sh` / `run.sh` renamed to `build` / `run`** —
   wrappers are still in place for one release; update CI scripts and
   docs at your leisure.
5. **`FORGATHER_HOME` is gone** — use the standard
   `~/.config/forgather/` path or override via `platformdirs` env vars.
6. **`uvicorn` is pinned to `>= 0.46, < 0.47`** — the mTLS protocol shim
   subclasses uvicorn's private protocol paths.
